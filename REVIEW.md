# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Grace period threshold check `minutes > 10` fails at the boundary. At `09:40:01` (601 seconds), `int(601/60) = 10`, and `10 > 10` evaluates to `False`, returning 0 instead of 10. Also ignores IST timezone conversion and overnight shift boundaries. | Punch in at 09:40:01 for a 09:30 shift; expected `late_minutes: 10`, received `0`. | Converted punch time to IST, checked `(punch_in - start).total_seconds() > 600` strictly, and floored elapsed minutes from `shift_start`. |
| 2 | `compute_work_hours` (lines 40–41) | Uses Python's built-in `round()`, which applies round-half-to-even (banker's rounding) and suffers from floating-point representation errors instead of exact half-up rounding (R4). | E.g. `(9630s / 3600) = 2.675` rounds to `2.67` with banker's rounding instead of `2.68`. | Used standard library `decimal.Decimal` with `ROUND_HALF_UP` on truncated whole-second durations. |
| 3 | `compute_overtime` (lines 44–47) | Missing the mandatory 30-minute minimum threshold (R3). Any duration > 0 is returned. Also does not handle overnight shifts where `shift_end` is on the next calendar day. | Punch out 15 minutes after shift end; expected `overtime_minutes: 0`, received `15`. For overnight shift (22:00–06:00), `end` is set to day 1 instead of day 2. | Added check that minutes must be `>= 30` (otherwise 0) and adjusted `shift_end` date by +1 day for overnight shifts (`shift_end <= shift_start`). |
| 4 | Missing `compute_half_day` helper | Rule R5 mandates `half_day = True` when rounded `work_hours < 4.50`. Starter hardcodes `half_day = False`. | Punch out after 4.0 hours; record retains `half_day: false` instead of `true`. | Added helper evaluating `work_hours is not None and work_hours < 4.50`. |
| 5 | `GET /health` (lines 72–74) | Returns unconditional `{"status": "ok"}` without verifying database connectivity. | Stop MongoDB and query `/health`; returns 200 OK instead of 503 Service Unavailable. | Added `client.admin.command('ping')` probe; returns 503 on `PyMongoError`. |
| 6 | `POST /employees` (lines 77–86) | Race condition on `emp_code` uniqueness due to `find_one` pre-check without unique index. Also does not validate that `shift_start != shift_end`, and returns `created_at` as ISO string rather than epoch milliseconds. | Concurrent duplicate `POST /employees` creates duplicate records. Equal shift times accepted. `created_at` is a string in JSON. | Added startup unique index on `emp_code`, handled `DuplicateKeyError` to return 409, validated `shift_start != shift_end` (422), and converted `created_at` to epoch milliseconds. |
| 7 | `GET /employees` (lines 88–96) | Pagination skip formula is `page * page_size`, skipping the entire first page (page 1 skips 20 items). `total` ignores the department filter. Results are not sorted by `emp_code`. | Requesting `page=1&page_size=20` returns items 21–40. Total count does not match filtered department. | Changed skip to `(page - 1) * page_size`, applied `db.employees.count_documents(q)` for total, and added `.sort("emp_code", 1)`. |
| 8 | `POST /attendance/punch-in` (lines 99–122) | Missing 404 check when employee does not exist (causes 500 `TypeError` on `emp['shift_start']`). Race condition on `find_one` allows duplicate punch-ins on same date. Leak of `id` field violating schema. Returns datetime instead of epoch ms. | Unknown employee returns 500. Concurrent identical punch-ins produce duplicate logs. Response contains `"id": "..."`. | Added 404 if employee missing, added unique compound index `(emp_code, date)` returning 409 on `DuplicateKeyError`, removed `id` field, and returned epoch ms. |
| 9 | `POST /attendance/punch-in` timestamp validation | Does not validate epoch milliseconds: accepts values below 100000000000 (which look like seconds) or floats without returning 422. Local system time used instead of IST calendar date. | Send `punched_at: 1783309200` (seconds); accepted instead of returning 422. Punching in after midnight on overnight shift assigns wrong calendar day. | Added Pydantic validator rejecting timestamps < 100000000000, floats, and strings; implemented R1 overnight shift date attribution. |
| 10 | `GET /attendance` (lines 124–150) | In-memory fetch and sort: loads all documents (`list(db.attendance_logs.find(q))`) into Python memory and sorts with Python `sort()`, causing OOM and latency on 100k records. Leaks `id` field. | High latency / timeout on 100k records. Response items contain `"id": "..."` instead of addressing by `(emp_code, date)`. | Replaced with database-level `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`, removed `id` assignment, and transformed BSON dates to epoch ms. |
| 11 | Missing database indexes at startup | Application does not create any indexes on startup, violating contract requirement for idempotent index initialization and causing collection scans (`COLLSCAN`). | Running `GET /admin/explain/attendance_list` shows `COLLSCAN` across whole collection. | Implemented `@app.on_event("startup")` / lifespan handler creating unique indexes on `employees.emp_code`, `attendance_logs.(emp_code, date)`, and query indexes. |
| 12 | Missing 7 required endpoints | Endpoints for punch-out, regularization, monthly analytics, department summary, late leaderboard, department trend, and admin explain are not implemented. | Requesting any of these endpoints returns 404 Not Found. | Implemented all missing endpoints adhering strictly to OpenAPI 2.0.0 contracts and R1–R10 rules. |

### Examined and Decided Was Not a Defect

1. **`db` initialization at module level**: Using a global PyMongo client instance is standard in FastAPI / Uvicorn with PyMongo's built-in connection pooling.
2. **`history: []` initialized at punch-in**: Correct per contract; punch-in and punch-out are original events and must never write to history, so initializing as empty list matches `DATA_MODEL.md`.
3. **Strings for calendar dates (`date`, `joined_on`, `shift_start`)**: Plain strings `YYYY-MM-DD` and `HH:MM` are intentional per `DATA_MODEL.md` to prevent unintended timezone offsets.
